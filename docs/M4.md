# M4 — advanced cache representations

M4 extends the existing in-process, single-GPU vLLM 0.34.0 connector. It
retains synchronous loads and asynchronous, deferred-free saves. Source
changes are made locally and rsynced to the GPU checkout before testing.

## Implementation

- The adapter returns a descriptor and placement **per engine group**.
  MLA preserves `head_size_v=0`; content width and head slots come from
  authoritative byte metadata. Compressed states use exact rational
  `tokens_per_state`. Whole-page alignment padding is copied verbatim.
- Sliding-window matching searches candidate boundaries from longest to
  shortest. Every group must supply its required pages at the same boundary,
  aligned to the least common multiple of group block sizes. Window groups
  require only blocks intersecting the trailing
  `window - 1 + extra_retained_tokens` interval. Null/dead block IDs never
  become copy destinations. Hashes still incorporate the entire prefix.
- `SupportsHMA.request_finished_all_groups` produces independent save plans.
  Request ownership ends only when **all** group tickets complete.
  `get_loaded_kv_cache_group_ids` reports the planned restored groups.
  Save plans exclude sampled tokens not yet evaluated by the model.
- Fingerprint version 3 includes semantic geometry and a model/revision,
  group-ID and ordered-layer namespace. Distinct groups cannot share store
  pages just because their byte geometry matches. Older fingerprints miss.
- Per-tensor FP8 captures checkpoint K/V scales into the fingerprint.
  Consumers must have identical scales; restoring a page never mutates a
  layer-global scale that other requests may use. Tensor mutation versions
  and CPU scale mirrors guard against changes without hot-path device sync.
  Dynamic per-tensor calibration is rejected. Inline quantization requires
  explicit content geometry; unknown scale contracts fail closed.
- Reservations are reference-counted across requests. Failed boundary probes,
  repeated lookups, rejected allocation, and multi-group load failures release
  their reservations. One group's completion cannot free another's sources.

## Validated scope and limits

| Representation | Implementation | Validation |
|---|---|---|
| Full + sliding hybrid | Per-group lookup, restore-trim, HMA completion | Gemma-2-2B-IT pretrained weights; 4,352-token shared prefix exceeds its 4,096-token window |
| MLA | Single latent plane; same-format reuse | Two-layer DeepSeek-V2 with seeded dummy weights, real vLLM MLA kernels |
| Padded/compressed MLA | Whole-page padding; integer/fractional state geometry | Adapter matrix; CUDA poison/restore into fresh buffers; projected latent continuation |
| Sparse index | Explicit indexer-role metadata, opaque passthrough | Compressed descriptor and GPU fixture; no full DeepSeek-V4 model run |
| Per-tensor FP8 | Captured immutable K/V scales | Scale mutation/identity tests; model validation recorded in TESTLOG |
| Inline FP8/INT8/INT4 per-token-head; NVFP4 DS-MLA | Explicit inline byte geometry, same-mode only | Descriptor tests; no claim of all backend/model combinations |
| Recurrent/Mamba/GDN | Rejected | No-go spike below |

Cross-kind and quantization-mode conversions are unsupported. Layout codecs
remain restricted to unquantized, unpadded full attention. Mixed physical
formats within a *single* group, padded kernel-block splits, and padded
head-fragmented pages fail registration. This milestone does not add
multi-process scheduler/worker coordination, distributed sharding, or a
production-scale DeepSeek-V4/Qwen3-Next model validation.

## Recurrent semantic-validation spike: NO-GO

Inspected the installed vLLM 0.34.0 source on the GPU host:

- `vllm/v1/core/single_type_kv_cache_manager.py`: Mamba align-mode code around
  lines 1890–1925 queues `(request_id, group_id, cow_block, boundary_tokens)`
  in `_pending_boundary_state_offloads`, after moving hashes and scheduling
  a copy-on-write operation. The preserved boundary state is not equivalent
  to the current state in the positional block table.
- The manager's boundary-offload handoff and pending CoW copies have their
  own ordering. The existing request-finished page-save lifecycle does not
  observe and acknowledge these boundary snapshots.
- `research.md` §7.3 requires boundary-semantic keys and L4 continuation
  equivalence, not a successful copy of opaque recurrent bytes.

There is insufficient evidence to certify recurrent restores using this
connector lifecycle. Recurrent caching is therefore explicitly rejected at
registration, including recurrent groups inside a hybrid engine. A future
implementation must consume boundary-offload metadata, fence behind CoW,
retain those exact snapshot blocks, and prove continuation equivalence in
align mode. No claim is made that a Qwen3-Next recurrent hybrid is supported.

## Reproducing validation

Run these in the remote project after syncing local changes:

```sh
.venv/bin/pytest tests/unit tests/integration/test_m4_gpu.py -q
HF_HUB_OFFLINE=1 .venv/bin/python tests/integration/m4_run.py hybrid connector /tmp/hybrid-c.json
HF_HUB_OFFLINE=1 .venv/bin/python tests/integration/m4_run.py hybrid baseline /tmp/hybrid-b.json
HF_HUB_OFFLINE=1 .venv/bin/python tests/integration/m4_run.py hybrid pcache /tmp/hybrid-n.json
.venv/bin/python tests/integration/m4_compare.py /tmp/hybrid-c.json /tmp/hybrid-b.json /tmp/hybrid-n.json
.venv/bin/python tests/integration/m4_bench.py
```

Repeat the three model runs with `mla` or `fp8`. Each invocation creates a
fresh engine. The Gemma checkpoint path is defined in `m4_run.py`; the tiny
MLA config is generated as a test artifact under `/tmp`. No downloaded
model weights are changed. `--no-verify` disables diagnostic GPU readback
for timing runs; hidden-state instrumentation remains enabled.

Acceptance compares eight continuation steps. Native-cache reuse must match
exactly in generated tokens, final-layer hidden states and top-5 logprobs.
Full recomputation must match greedy tokens and have hidden-state cosine
at least 0.999. Exact recompute differences are reported, not suppressed.
Full-vocabulary logit KL and a broad prompt corpus are not measured here.
See TESTLOG for observed results and timing limitations.
